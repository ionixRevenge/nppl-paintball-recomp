# NPPL Championship Paintball 2009 — PC Port (static recompilation)

A native PC port of **NPPL Championship Paintball 2009** (PS2, USA, `SLUS-218.55`), built by **static
recompilation**: `recomp/recomp.py` translates every function of your own copy of the game's executable into C,
and `runtime/` replaces the PS2 hardware (CPU helpers, memory, kernel, graphics, sound, input). Functions can
later be swapped for hand-decompiled C one at a time.

> This repository contains **no game data**. Put your own dump of the game in `game_iso/`; everything else
> (`iso/`, `asm/`, `assets/`, `build/`) is generated from it locally and git-ignored.

## Current state: playable, work in progress

The game boots, runs through the menus and **plays full career matches** on PC: correct textures, music and
sound (ADPCM streams), memory-card saves, and XInput controllers. A Direct3D 11 renderer draws at 2× resolution
by default (`-scale N`) and runs gameplay at roughly 45–50 fps on a 4-core laptop.

**Known issues**

* **Bunker collision:** running into a bunker head-on at full speed briefly "catches" the player for a split
  second before releasing (PCSX2 is smooth there). The older bug where players and bots stuck to nets, bunkers
  and corners permanently is fixed.
* Intro/cutscene movies (`.PSS`) are skipped (no IPU/MPEG-2 decoding yet).
* Destination-alpha testing and mipmaps aren't implemented in the renderer yet (only the base texture level is used).

**Planned**

* **Upscaling:** higher-resolution textures and rendering. A GPU xBR texture filter (`-texscale 1|2|4`) and an
  offline upscaling tool (`tools/upscale_textures.py`) are early steps; proper upscaled texture packs come later.
* Fixing the bunker collision catch and the other issues above.

## Setup

**You must provide your own ISO.** Put your dump of *NPPL Championship Paintball 2009* (USA, `SLUS-21855`)
in `game_iso/` as a `.iso` file. Known-good SHA-1: `8db77412f8d920d6b742269deb8c5c0ec7b5e4f1`.

Requirements: Python ≥ 3.9, and the ps2dev EE binutils (`mips64r5900el-ps2-elf-as/ld/objcopy`).

```sh
py -3.12 -m venv .venv
.venv/Scripts/python -m pip install "splat64[mips]" spimdisasm rabbitizer ninja
git config core.hooksPath tools/hooks   # blocks accidental commits of game data

# Toolchain: extract the ee/bin folder of the ps2dev release to tools/ps2dev/
#   https://github.com/ps2dev/ps2dev/releases (ps2dev-windows-latest.tar.gz)

.venv/Scripts/python configure.py      # verifies + extracts game_iso/*.iso, runs splat, writes build.ninja
.venv/Scripts/ninja                    # assembles, links, compares to original
```

`configure.py` runs `tools/setup_iso.py`, which checks the disc's volume ID and the SHA-1 of the executable and
`DATA.ARC`, then extracts it to `iso/` (skipping the 3 GB of `TRASH/` padding). Other dumps of the same release
are accepted as long as those files match.

`ninja` succeeds only if the rebuilt main segment is byte-identical to the original.

## Building the PC version

Requirements: everything from Setup above, plus Visual Studio 2022 (C++ workload) and CMake.

```sh
.venv/Scripts/python configure.py --no-split          # verify/extract the ISO (if not done yet)
.venv/Scripts/python recomp/recomp.py iso/SLUS_218.55 build/recomp
cmake -S runtime -B build/pc -G "Visual Studio 17 2022" -A x64
cmake --build build/pc --config Release
build/pc/Release/nppl_pc.exe game_iso                  # your ISO or its folder; -v for a full trace; log: ps2rt.log
```

## Public release rules

This project is meant to be published, so the repository contains **only original work**: tools, build
scripts, configuration (addresses and names), and hand-written decompiled C/C++.

* **Never commit** anything from `game_iso/`, `iso/`, `asm/`, `assets/` or `build/`. These are copyrighted
  game data or derived from it. `.gitignore` excludes them and the `tools/hooks/pre-commit` hook refuses
  game-derived paths, binaries and very large files.
* **Releases ship no game data.** A PC build should load assets at runtime from the player's own extracted disc
  (`iso/DATA/DATA.ARC`, `iso/DATA/MOVIES/*.PSS`), produced by the same `setup_iso.py` step.
* **Licensed libraries are replaced, not published.** Sony's SDK, Havok 5.5 and Kynapse are commercial
  libraries. Decompiled copies of them must not be released. The port replaces them (see the porting plan),
  and the game's own code calls the replacements through the same interfaces.
* This is not legal advice. Fan decomps are usually published this way (code only, bring your own disc), but
  that carries no guarantee.

## Decompiling a function

1. Pick a function in `src/*.c` (`INCLUDE_ASM("asm/nonmatchings/...", func_XXXXXXXX);`).
2. Get the asm from `asm/nonmatchings/...`, decompile it (e.g. on decomp.me with an `mwcps2` compiler preset, or m2c).
3. Replace the `INCLUDE_ASM` line with C, and name things in `config/symbol_addrs.txt`.
4. Rebuild with a real compiler: `configure.py --cc <compiler>`.
   * **Matching:** an MWCC PS2 compiler as close to 2.4.1 as you can get.
   * **Non-matching / porting:** any compiler; correctness is then checked by behavior, not bytes.

## Porting plan

The static recompilation above already makes the game playable. These are the longer-term steps toward a
cleaner port that doesn't depend on recompiled middleware:

1. **Split + label:** identify the SCE, libc, zlib and Havok functions so they can be replaced.
2. **Decompile game + engine code** (~0x140000–0x530000 and the AI code). This is the actual game.
3. **Replace platform layers:** SCE libs → SDL3 (input, audio, files, timing); GS/VIF/VU1 renderer → OpenGL/Vulkan backend.
4. **Replace middleware:** Havok 5.5 → an open physics engine (e.g. Jolt), Kynapse → a reimplementation of the pathfinding queries the game uses.
5. **Assets:** `tools/arc_tool.py` catalogs and unpacks `DATA.ARC` (a series of zlib streams); file names are resolved by the game's loader.

## Tools

| Tool | Purpose |
|---|---|
| `tools/setup_iso.py` | Find, verify and extract the ISO from `game_iso/` |
| `tools/extract_iso.py` | Unpack an ISO9660 disc |
| `tools/hooks/pre-commit` | Blocks commits of game data |

| `recomp/recomp.py` | Static recompiler: executable → C (output in `build/recomp`, never committed) |
| `runtime/` | PC runtime the recompiled code runs on |
